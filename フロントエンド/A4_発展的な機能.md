## 1. 非同期処理と Push

### 問題

リスナーの中で、**長い処理**（大量のデータの集計、外部のサービスの呼び出し）をすると、その間、**画面が固まります**（[06 章](06_イベントと画面の仕組み.md)）。

### 非同期にする

長い処理は、**別のスレッド**で実行し、終わったら、画面を更新します。ここで、**別のスレッドから、直接コンポーネントを触ってはいけません**。`ui.access(...)` を使います。

```java
var ui = UI.getCurrent();
CompletableFuture.supplyAsync(() -> 重い集計())           // 別のスレッドで実行
    .thenAccept(結果 -> ui.access(() -> {                  // 画面の更新は、ui.access で
        一覧.setItems(結果);
        Notification.show("集計が終わりました");
    }));
```

### Push

画面の更新は、通常、**利用者の操作に対する応答**として行われます。操作がなくても、**サーバーから画面を更新**する（集計の完了を知らせる）には、**Push** が必要です。

| 方式 | 内容 |
|---|---|
| 既定 | 利用者の操作があったときだけ、画面が更新される |
| **Push**（`@Push`） | サーバーから、ブラウザに、いつでも変更を送れる（WebSocket など） |

```java
@Push                                                  // 起動クラスなどに付ける
public class Application implements AppShellConfigurator { … }
```

> [!WARNING]
> Push は、**サーバーとの接続を、つなぎ続ける**ので、利用者が多いと、サーバーの負荷が上がります。本当に必要な場面（長い処理の完了、リアルタイムの表示）に、限ります。

## 2. 国際化（i18n）

**国際化**は、画面の文言を、**言語に応じて切り替える**仕組みです。利用者が、日本語・英語を、選べるようにします。

| 項目 | 内容 |
|---|---|
| 文言のファイル | `src/main/resources/vaadin-i18n/translations.properties`（既定）、`translations_en.properties`（英語） |
| 取得 | `getTranslation("app.title")`（コンポーネントの中で） |
| 言語の切り替え | `UI.getCurrent().setLocale(Locale.ENGLISH)` |
| 提供の仕組み | `I18NProvider`（Spring の Bean として、実装する） |

```properties
# translations.properties（日本語）
app.title=成績管理システム
# translations_en.properties（英語）
app.title=Grade Management System
```

> [!TIP]
> **ユーザビリティの視点**：最初から、画面の文言を、**直接コードに書かず、文言のファイルに分けて**おくと、後から多言語に対応しやすくなります。ただし、**対応する必要がない**（日本語だけ）ならば、無理に分ける必要はありません。「どの利用者が、どの言語で使うか」を、上流工程で確認します。

> [!NOTE]
> 日付・数値の表示形式（`2026/11/19` と `11/19/2026`）も、言語（ロケール）で変わります。`DatePicker` の表示形式は、ロケールに従います。

## 3. ファイルのアップロード

Vaadin には、ファイルのアップロードの部品（`Upload`）があります。成績では、「成績の一括登録（CSV）」などの場面があります。

| 項目 | 内容 |
|---|---|
| 部品 | `Upload`（ファイルを選んで、サーバーに送る） |
| 受け取り | `UploadHandler` や、`Receiver` で、ファイルのデータを受け取る（具体的な API は、使うバージョンの公式ドキュメントで確認する） |

**既定の表示**（文言は、英語です）

<!-- snippet: advanced-upload-default -->
```java
var アップロード = new Upload();
アップロード.setAcceptedFileTypes(".csv");
アップロード.setMaxFiles(1);
```

<img src="../images/frontend/app/parts/advanced-upload-default.png" alt="既定の Upload（「Upload File...」「Drop file here」と、英語で表示される）" width="444">

`setAcceptedFileTypes` と `setMaxFiles` は、**画面の設定**です。**サーバー側でも、必ず確認**します（下の注意）。文言は、`UploadI18N` で、日本語にします。

<!-- snippet: advanced-upload-japanese -->
```java
var アップロード = new Upload();
アップロード.setAcceptedFileTypes(".csv");
アップロード.setMaxFiles(1);
アップロード.setI18n(new UploadI18N()
        .setDropFiles(new UploadI18N.DropFiles()
                .setOne("成績の CSV ファイルを、ここにドロップ")
                .setMany("ファイルを、ここにドロップ"))
        .setAddFiles(new UploadI18N.AddFiles()
                .setOne("ファイルを選ぶ")
                .setMany("ファイルを選ぶ")));
```

<img src="../images/frontend/app/parts/advanced-upload-japanese.png" alt="日本語にした Upload" width="444">

> [!CAUTION]
> **セキュリティの視点**：アップロードされるファイルは、**信用してはいけません**。次の点を、**サーバー側で**確認します（画面の設定だけでは、回避される）。
>
> | 確認 | 内容 |
> |---|---|
> | **大きさの上限** | 大きなファイルで、サーバーを止められないように |
> | **種類（拡張子・中身）** | 許可する種類だけ（CSV など）。拡張子だけでなく、**中身も確認** |
> | **ファイル名** | 利用者が決めた名前を、そのまま保存先のパスに使わない（`../../` で、別の場所に書かれる）。**サーバー側で、名前を決め直す** |
> | **保存場所** | 実行できる場所に、置かない。Web から直接アクセスできる場所に、置かない |
> | **中身の検査** | CSV なら、1 行ずつ、Domain のルールで検査する（画面の入力と、同じ扱い） |

## 4. Signals

**Signals** は、画面の**状態**（値）を、**変化に応じて、自動で画面に反映する**ための、新しい仕組みです（リアクティブな状態管理）。公式ドキュメントの「UI State」の章に、説明があります。

<!-- snippet: advanced-signal -->
```java
var 件数 = new ValueSignal<>(3);                              // 値を持つ Signal
var ラベル = new Span();
ラベル.bindText(件数.map(n -> "登録した件数：" + n));            // 値に応じて、文字が自動で決まる
```

<img src="../images/frontend/app/parts/advanced-signal.png" alt="ValueSignal の値から作った文字（登録した件数：3）" width="144">

値の変更の API（`set` など）は、使うバージョンの公式ドキュメントで確認してください。

| 種類 | 内容 |
|---|---|
| **ローカル**（ValueSignal など） | 1 つの画面（1 人の利用者）の中での、状態 |
| **共有**（SharedValueSignal など） | **複数の利用者**で、共有する状態（共同編集、リアルタイムの表示）。Push が必要 |

> [!NOTE]
> Signals は、新しい機能で、**API が、バージョンによって変わる可能性**があります。公式ドキュメントの該当ページは、最新の（先行の）バージョンの内容が、表示されていることがあります。**使う前に、使っているバージョンで、利用できる機能か、確認**してください（<https://vaadin.com/docs/latest/flow/ui-state>）。この資料では、概要の紹介にとどめます。

> [!TIP]
> **従来の書き方**（リスナーで、値の変更のたびに、`setText` を呼ぶ）でも、十分に、画面を作れます。**状態が複雑になってきたとき**に、Signals の利用を、検討します。

## 5. よくあるミス

| ミス | 原因・対処 |
|---|---|
| 別のスレッドから、直接、コンポーネントを更新して、例外 | `ui.access(...)` で、包む |
| `@Push` を、すべてのアプリに付ける | 接続を保つため、負荷が上がる。必要なときだけ |
| アップロードの種類・大きさを、画面の設定だけで、制限する | サーバー側でも、確認する |
| アップロードされたファイル名を、そのまま保存先に使う | パスの操作の攻撃。名前は、サーバーで決める |
| 文言を、コードに、直接書いて、後から多言語化できない | 必要になりそうなら、最初から、文言を分ける |
| Signals の API を、古い／先行版の記事から写す | 使っているバージョンで、確認する |
