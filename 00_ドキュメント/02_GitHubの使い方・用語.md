## 1. Git / GitHub とは？
![GitとGitHubの画像](/images/git_github.png)
### Git（ギット）
ファイルの**変更履歴を記録・管理するツール**（バージョン管理システム）です。自分のパソコンの中で動きます。

こんな経験はありませんか？

```
レポート.docx
レポート_最終.docx
レポート_最終_修正版.docx
レポート_最終_修正版_本当に最終.docx
```

Git を使うと、**ファイルは1つのまま**で「いつ・誰が・何を変えたか」が全部記録され、好きな時点に戻れます。

### GitHub（ギットハブ）
Git で管理しているデータを**インターネット上に保存・共有するサービス**です。

| | Git | GitHub |
|---|---|---|
| 正体 | 管理するための**ツール** | 共有するための**Webサービス** |
| 動く場所 | 自分のパソコン | インターネット上 |
| たとえ | 履歴管理の仕組み | Git の置き場所＋チーム作業の場 |

### 何が嬉しいの？
- 間違えても**元に戻せる**
- 複数人が**同じファイルを同時に**編集しても、あとで合体できる
- 誰がいつ何を変えたか**追跡できる**
- パソコンが壊れても GitHub にデータが残る

## 2. 基本用語集

### 場所に関する用語

| 用語 | 意味 | たとえ |
|---|---|---|
| **リポジトリ (repository / repo)** | 管理対象のフォルダ＋その変更履歴の全体 | プロジェクト専用の保管庫 |
| **ローカルリポジトリ** | 自分のパソコン内のリポジトリ | 手元のノート |
| **リモートリポジトリ** | GitHub 上のリポジトリ | クラウド上の共有ノート |
| **origin** | リモートリポジトリにつけられた**標準の呼び名** | 「共有ノート」という愛称 |

### 履歴に関する用語

| 用語 | 意味 |
|---|---|
| **コミット (commit)** | 変更を「1つの記録」として保存すること。または、その記録そのもの。ゲームのセーブポイントのようなもの |
| **コミットメッセージ** | コミットにつける「何を変えたか」の説明文（例：`READMEに手順を追加`） |
| **履歴 (log)** | コミットが時系列に並んだもの |
| **差分 (diff)** | 変更前と変更後の違い |
| **HEAD** | 「今自分がいる場所（最新のコミット）」を指す目印 |

### 作業の流れに関する用語

| 用語 | 意味 |
|---|---|
| **ワーキングツリー（作業ディレクトリ）** | 実際にファイルを編集している場所 |
| **ステージング (staging)** | 「次のコミットに含めるファイル」を選んで準備すること |
| **ステージングエリア (index)** | コミット前の「準備置き場」 |
| **add** | 変更をステージングエリアに載せる操作 |
| **push（プッシュ）** | 自分のコミットを GitHub に**送る**操作 |
| **pull（プル）** | GitHub の最新の内容を自分のパソコンに**取り込む**操作 |
| **clone（クローン）** | GitHub のリポジトリを自分のパソコンに**丸ごとコピー**する操作（最初に1回だけ） |
| **fetch（フェッチ）** | GitHub の最新情報を**確認だけ**する操作（自分のファイルは変わらない） |

### 並行作業に関する用語

| 用語 | 意味 |
|---|---|
| **ブランチ (branch)** | 履歴の「枝分かれ」。本流に影響を与えずに作業できる別ルート |
| **main（メイン）ブランチ** | 本流となるブランチ。完成版を置く場所 |
| **checkout / switch** | ブランチを切り替える操作。切り替えると、作業フォルダのファイルがそのブランチの内容に置き換わる |
| **未コミットの変更** | 編集したがまだコミットしていない変更（ローカルの変更とも呼ぶ） |
| **スタッシュ (stash)** | 未コミットの変更を**一時的に退避**させる機能（取り置き）。あとで元に戻せる |
| **適用 / ポップ (apply / pop)** | 退避した変更を作業フォルダに戻す操作。pop は戻したあとスタッシュからも削除する |
| **シェルフ (shelve)** | IntelliJ IDEA 独自の退避機能。スタッシュとほぼ同じ働き |
| **マージ (merge)** | 別のブランチの変更を合体させる操作 |
| **コンフリクト (conflict)** | 同じ場所を別々に編集して、**自動で合体できない**状態（後述） |
| **プルリクエスト (Pull Request / PR)** | 「自分の変更を main に取り込んでください」と GitHub 上で依頼する機能 |
| **フォーク (fork)** | 他人のリポジトリを自分のアカウントにコピーすること |

### ブランチのイメージ
![ブランチイメージ画像](/images/ブランチイメージ.png)

自分のブランチで自由に作業し、完成したら main に合体（マージ）します。失敗しても main は無傷です。

## 4. 最初の準備（初回のみ）

### 4-1. GitHub アカウントの作成
Git の設定（4-3）で **GitHub に登録したメールアドレス**を使うため、先にアカウントを作成します。

1. https://github.com を開き、**Sign up** をクリックする。
2. **メールアドレス**・パスワード・ユーザー名を入力する。
3. 認証パズルを解き、メールに届く**確認コード**を入力する。
4. アンケート画面などは「Skip」でOK。
5. 作成したら、**ユーザー名**と**登録したメールアドレス**を控えておく（次の手順で使います）。

> **メールアドレスを公開したくない場合**
> GitHub の **Settings → Emails** で「Keep my email addresses private」にチェックを入れると、`ユーザー名@users.noreply.github.com` 形式の非公開用アドレスが発行されます。4-3 ではこのアドレスを使ってもOKです。

### 4-2. Git のインストール
まず、すでにインストールされているか確認します。ターミナル（Windows は PowerShell かコマンドプロンプト）で次を実行し、バージョンが表示されればインストール済みです（4-3 へ進んでOK）。

```bash
git --version
```

「command not found」や「'git' は、内部コマンドまたは外部コマンド…として認識されていません」と出た場合は、下記の手順でインストールします。

#### Windows の場合

1. 公式サイト https://git-scm.com/download/win を開く（自動でダウンロードが始まります。始まらない場合は「Click here to download manually」をクリック）。
2. ダウンロードした `Git-x.x.x-64-bit.exe` を実行する。
3. インストーラーの画面は基本的にすべて **「Next」** のままでOK。最後に「Install」→「Finish」をクリック。
4. **開いているターミナル／VS Code をいったんすべて閉じて、開き直す**（開き直さないと認識されません）。
5. 次のコマンドでバージョンが表示されれば完了。

```powershell
git --version
```

> **winget を使う方法（コマンドでインストール）**
> PowerShell で次を実行しても同じようにインストールできます。
> ```powershell
> winget install --id Git.Git -e --source winget
> ```

#### Mac の場合

**方法A：Xcode Command Line Tools（一番かんたん・おすすめ）**

1. ターミナルを開き、次を実行する。

```bash
git --version
```

2. 未インストールの場合は「コマンドライン・デベロッパ・ツールが必要です」というダイアログが出るので **「インストール」** をクリックする。
   （出ない場合は `xcode-select --install` を実行）
3. インストールが終わるまで数分待ち、再度 `git --version` でバージョンが表示されれば完了。

**方法B：Homebrew を使う**

すでに Homebrew を入れている人は、次のコマンドで最新版の Git をインストールできます。

```bash
brew install git
```

> インストール後、ターミナルを開き直してから `git --version` で確認してください。

### 4-3. 名前とメールアドレスの設定
コミットに「誰が書いたか」が記録されるため、最初に登録します。メールアドレスは **4-1 で GitHub に登録したもの**を使います。

```bash
git config --global user.name "あなたの名前"
git config --global user.email "GitHubに登録したメールアドレス"
```

設定の確認:

```bash
git config --global --list
```

### 4-4. GitHub への認証設定（push するために必要）
GitHub は 2021 年から、Git 操作での**パスワード認証を廃止**しています。そのため `git push` するには、次のいずれかで本人確認が必要です。**clone や pull だけなら（公開リポジトリは）不要**ですが、push の時点で必ず求められます。

**使う道具（ターミナル／VSCode／IntelliJ IDEA）によって設定方法が違う**ので、自分が使うものに合わせて手順を読んでください。

| 使う道具 | 認証の方法 | 難易度 |
|---|---|---|
| [**ターミナル（Windows）**](#windows) | Git Credential Manager（Git に同梱。初回 push 時にブラウザが開く） | ★ かんたん |
| [**ターミナル（Mac）**](#mac) | Personal Access Token (PAT) を Password 欄に入力 → Keychain に保存 | ★★ やや手間 |
| [**VSCode**](#4-4-2-vscode-を用いる場合) | VSCode から GitHub にサインイン（ブラウザで承認） | ★ かんたん（おすすめ） |
| [**IntelliJ IDEA**](#4-4-3-intellij-idea-を用いる場合) | 設定で GitHub アカウントを追加（ブラウザ or PAT） | ★ かんたん |

> どの道具でも、うまくいかないときの最終手段は **PAT**（次の「PAT の発行手順」）です。


#### Personal Access Token (PAT) の発行手順

パスワードの代わりに使う「合言葉」を自分で発行します。Mac のターミナルや IntelliJ IDEA（トークンでログインする場合）で使います。

1. GitHub にログインし、右上のアイコン → **Settings** を開く。
2. 左メニューの一番下 **Developer settings** → **Personal access tokens** → **Tokens (classic)** を選ぶ。
3. **Generate new token (classic)** をクリックする。
4. 次のように入力する。
   - **Note**：`講義用PC` など用途が分かる名前
   - **Expiration**：`90 days` など（各自に任せます）
   - **Select scopes**：**`repo`** にチェック（IntelliJ IDEA で使う場合は、加えて **`gist`**・**`read:org`** にもチェック）
5. **Generate token** をクリックする。
6. 表示された `ghp_xxxxxxxx...` を**必ずその場でコピー**する（**この画面を閉じると二度と表示されません**）。

> ⚠️ **トークンはパスワードと同じ扱いです**
> - 他人に教えない／ファイルやコミットに書かない／スクリーンショットに写さない
> - 流出したら、同じ画面から **Delete** してすぐ無効化する

### 4-4-1. ターミナルで行う場合

#### Windows
Git for Windows には **Git Credential Manager** が標準で同梱されているため、特別な設定は不要です。

1. ターミナル（PowerShell）でリポジトリのフォルダに移動し、`git push` を実行する。
2. 初回だけ **ブラウザのログイン画面（またはダイアログ）** が自動で開く。
3. **Sign in with your browser** を選び、GitHub にログインして **Authorize** をクリックする。
4. push が成功すれば完了。以降は自動でログイン情報が使われ、入力不要。

> ログイン画面が出ずに失敗する場合は、下の Mac と同じく PAT を使います。

#### Mac
Mac のターミナルでは多くの場合ログイン画面が出ず、**Password: と聞かれる**ので、PAT を使います。

1. 上の手順で **PAT を発行**し、コピーしておく。
2. ターミナルで `git push` を実行する。
3. 次のように聞かれたら入力する。

```
Username for 'https://github.com': GitHubのユーザー名
Password for 'https://...@github.com': ← ここにトークンを貼り付ける
```

**パスワードではなくトークンを貼り付けます**（入力しても画面には何も表示されませんが、貼り付けられています）。

4. Mac では **Keychain に保存**され、2回目以降は入力不要です。

保存されない場合は、次で Keychain を使う設定を確認・追加します。

```bash
git config --global credential.helper          # osxkeychain と表示されればOK
git config --global credential.helper osxkeychain   # 何も表示されない場合に実行
```

> 認証情報が古くなってエラーが続くときは、「キーチェーンアクセス」アプリで `github.com` を検索して削除すると、次の push で再入力できます。

[↑ 認証設定の目次へ](#4-4-github-への認証設定push-するために必要)

### 4-4-2. VSCode を用いる場合

VSCode から GitHub にサインインするだけで、ターミナルを使わずに認証できます。

1. VSCode の左下（または左端）にある **アカウント** アイコンをクリックする。
2. **「GitHub でサインインしてプロファイルを同期」**（または「Sign in with GitHub」）を選ぶ。
   - 出てこない場合は、ソース管理で **push / 同期** を実行すると「GitHub にサインインしますか？」というダイアログが出るので **許可** する。
3. ブラウザが開くので GitHub にログインし、**Authorize Visual Studio Code** をクリックする。
4. 「VS Code を開きますか？」と出たら **開く** を選ぶ。
5. アカウントアイコンに自分のユーザー名が表示されれば完了。

あとは、ソース管理（Source Control）の「同期」や「プッシュ」で push できます（操作は[11. VSCode での操作](#11-補足vscode-での操作gui)を参照）。

> VSCode の認証は **VSCode 内の操作でのみ有効**です。同じ PC で別途ターミナルから `git push` する場合は、4-4-1 の設定も必要になることがあります。

### 4-4-3. IntelliJ IDEA を用いる場合

IntelliJ IDEA の設定に GitHub アカウントを登録します。

#### 方法1：ブラウザでログイン（おすすめ）

1. 設定画面を開く。
   - **Windows**：`File` → `Settings`（`Ctrl + Alt + S`）
   - **Mac**：`IntelliJ IDEA` → `Settings`（`⌘ + ,`）
2. 左メニューの **Version Control** → **GitHub** を開く。
3. **＋** ボタン →  **Log In via GitHub** をクリックする。
4. ブラウザが開くので GitHub にログインし、**Authorize in GitHub** をクリックする。
5. アカウント一覧に自分のユーザー名が表示されれば完了。**OK** で閉じる。

#### 方法2：PAT でログイン（方法1がうまくいかない場合）

1. 前述の手順で **PAT を発行**する（スコープは `repo`・`gist`・`read:org`）。
2. 手順 3 で **Log In with Token...** を選ぶ。
3. **Token** 欄に PAT を貼り付けて **Add Account** をクリックする。

#### リポジトリの clone（IntelliJ IDEA の場合）

1. ウェルカム画面の **Clone Repository**（または `File` → `New` → `Project from Version Control`）を開く。
2. 左の **GitHub** を選ぶと、登録したアカウントのリポジトリ一覧が表示される。
3. 対象のリポジトリを選び、**Directory**（保存先）を指定して **Clone** をクリックする。

#### push の方法
- メニューの `Git` → `Push...`（`Ctrl + Shift + K` / Mac は `⌘ + Shift + K`）
- 変更の確認・コミットは `Commit` ウィンドウ（`Ctrl + K` / Mac は `⌘ + K`）

> アカウントを登録せずに push すると、「Username / Password」の入力ダイアログが出ることがあります。その場合は **Password 欄に PAT を貼り付けます**。

[↑ 認証設定の目次へ](#4-4-github-への認証設定push-するために必要)

## 5. 基本の使い方（毎回の作業の流れ）
![gitサイクルイメージ](/images/gitサイクルイメージ.png)
### Step 0：作業前に最新を取り込む

```bash
git pull
```

> 他の人が更新しているかもしれないので、**作業を始める前に必ず pull** する習慣をつけましょう。

### Step 1：ファイルを編集する
VSCode などで普通にファイルを編集・追加・削除します。

### Step 2：状態を確認する

```bash
git status
```

「どのファイルが変更されたか」「ステージング済みか」が分かります。**迷ったらまず `git status`** です。

### Step 3：コミットしたいファイルを選ぶ（add）

```bash
git add ファイル名      # 特定のファイルだけ
git add .               # 変更したもの全部（. は「今のフォルダ全部」の意味）
```

### Step 4：記録する（commit）

```bash
git commit -m "〇〇〇に新規機能△△△を追加"
```

`-m` の後ろがコミットメッセージです。

### Step 5：GitHub に送る（push）

```bash
git push
```

### まとめ：1サイクル

```bash
git pull                          # ① 最新を取り込む
# ……ファイルを編集……
git status                        # ② 状態確認
git add .                         # ③ 選ぶ
git commit -m "変更内容の説明"      # ④ 記録
git push                          # ⑤ 送る
```

## 6. ブランチを使った作業

自分専用のブランチで作業すると、他の人の作業とぶつかりにくくなります。

```bash
git branch                    # ブランチ一覧（* が今いる場所）
git switch -c 新しいブランチ名   # ブランチを作って移動
git switch ブランチ名           # 既存ブランチへ移動
git switch main               # main に戻る
```

### 初めて push するブランチの場合

```bash
git push -u origin ブランチ名
```

`-u` は「このブランチは GitHub 上のこのブランチと対応させる」という設定で、2回目以降は `git push` だけで済みます。

### ブランチを切り替えるときに変更が残っている場合

コミットしていない変更が残った状態でブランチを切り替えようとすると、変更が**上書きされたり、別ブランチの内容と衝突したり**するおそれがあるため、GUI では確認ダイアログが表示されます。

> **迷ったら：切り替える前にコミットする**のが一番安全。コミットしておけば、ダイアログ自体が出ない。

ダイアログの選択肢は次のとおりです（VSCode の表示 / IntelliJ IDEA の表示）。

| 選択肢 | 何が起きるか | 変更の行き先 | 使う場面 |
|---|---|---|---|
| **スタッシュしてチェックアウト** / Smart Checkout | 変更をいったん退避してから切り替える。IntelliJ は切り替え後に自動で戻す | 退避場所（VSCode は元のブランチに戻って手動で適用する） | 変更を今のブランチのものとして残したいとき |
| **変更の移行** | 変更を持ったまま切り替え、**移動先のブランチ**に反映する | 移動先のブランチ | 間違ったブランチで作業を始めてしまったとき |
| **チェックアウトの強制** / Force Checkout | 変更を**破棄**して切り替える | 消える | 変更が不要なとき**だけ** |
| **キャンセル** / Don't Checkout | 何もせず、切り替えをやめる | そのまま | 迷ったとき（先にコミットする） |

> ⚠️ **チェックアウトの強制は、破棄した変更を元に戻せません。** 本当に不要な変更か確認してから選んでください。

> **変更の移行について**
> 移動先のブランチで同じ場所が違う内容になっている場合は、切り替えに失敗したり、コンフリクトになったりします。その場合は [9. 困ったときは](#9-困ったときは) の手順で解決するか、「スタッシュしてチェックアウト」を選び直してください。

#### 対応するコマンド

| 選択肢 | コマンド |
|---|---|
| スタッシュしてチェックアウト | `git stash` → `git switch ブランチ名` |
| 変更の移行 | `git switch ブランチ名`（変更を持ち越す） |
| チェックアウトの強制 | `git switch -f ブランチ名` |

退避した変更の確認と復元:

```bash
git stash list      # 退避した変更の一覧
git stash pop       # 最新の退避を戻す（戻したあと一覧から消える）
git stash apply     # 戻す（一覧には残る）
```

### main に取り込む（プルリクエスト）
1. 自分のブランチを push する
2. GitHub のリポジトリページを開き、**Compare & pull request** をクリック
3. 変更内容を書いて **Create pull request**
4. レビュー後、**Merge pull request** で main に合体

## 7. コマンド早見表

| やりたいこと | コマンド |
|---|---|
| 状態を見る | `git status` |
| 履歴を見る | `git log --oneline` |
| 変更内容（差分）を見る | `git diff` |
| 変更をステージに載せる | `git add ファイル名` / `git add .` |
| 記録する | `git commit -m "メッセージ"` |
| GitHub に送る | `git push` |
| GitHub から取り込む | `git pull` |
| リポジトリをコピー | `git clone URL` |
| ブランチ一覧 | `git branch` |
| ブランチを作って移動 | `git switch -c 名前` |
| ブランチを移動 | `git switch 名前` |
| 別のブランチの変更を、今いるブランチに取り込む（合体） | `git merge 取り込みたいブランチ名` |

> **merge の向きに注意**：`git merge` は「**今いるブランチ**に、**指定したブランチ**の変更を取り込む」コマンドです。先に取り込み先のブランチへ移動してから実行します。
>
> 例：`feature` ブランチの作業を `main` に合体したい場合
> ```
> git switch main        # ① 取り込み先（main）に移動
> git merge feature      # ② feature の変更を main に取り込む
> ```
> → 合体後、`main` は `feature` の内容を含み、`feature` は変わりません。

## 8. 良いコミットメッセージの書き方

| 悪い例 | 良い例 |
|---|---|
| `変更` | `課題2のグラフ描画関数を追加` |
| `修正` | `ログイン画面の文字化けを修正` |
| `aaa` | `README に環境構築手順を追記` |

- **何をしたかが1行で分かる**ように書く
- コミットは**意味のまとまりごと**に小さく分ける
- 「あとで自分が見て分かるか？」を基準にする

## 9. 困ったときは

### コンフリクト（衝突）が起きた
同じ場所を別々に編集すると、`git pull` や `merge` のときに衝突します。ファイルに次のような印が入ります。

```
自分の変更内容
```

**対処法**
1. 印（`<<<<<<<` `=======` `>>>>>>>`）を含めて、**残したい内容に手動で書き換える**
2. 印をすべて消す
3. `git add ファイル名` → `git commit` で完了

> VSCode では「Accept Current / Incoming / Both」というボタンが出るので、クリックで選べます。

### push が拒否された（rejected）
GitHub 側に自分が持っていない更新があるためです。先に `git pull` してから、もう一度 `git push` します。

### 直前のコミットメッセージを間違えた（push 前のみ）

```bash
git commit --amend -m "正しいメッセージ"
```

### 編集中の変更を取り消したい（コミット前）

```bash
git restore ファイル名
```

> ⚠️ **注意**: このコマンドで取り消した変更は**元に戻せません**。

### add を取り消したい（ステージから外す）

```bash
git restore --staged ファイル名
```

### 何が起きているか分からない
まず `git status` を実行し、表示されたメッセージをよく読みます。Git は次にやるべきコマンドのヒントを出してくれることが多いです。

## 10. やってはいけないこと・注意点

- ❌ **パスワードや API キーをコミットしない**（GitHub に上げると公開・流出の恐れ。一度上げたら消しても履歴に残る）
- ❌ **`git push --force` を安易に使わない**（他人の履歴を上書きして壊す可能性がある）
- ❌ **main ブランチで直接作業しない**（自分のブランチで作業してから取り込む）
- ❌ 巨大なファイル（動画・データセットなど）を入れない
- ✅ 作業前に `git pull`、作業後に `git push` を習慣にする
- ✅ こまめにコミットする（セーブポイントは多いほうが安心）

## 11. 補足：VSCode での操作（GUI）

コマンドが不安な場合は、VSCode の左サイドバーにある **ソース管理（Source Control）** アイコンからも同じ操作ができます。

| コマンド | VSCode での操作 |
|---|---|
| `git add` | 変更ファイルの「＋」ボタン |
| `git commit` | メッセージを入力して「コミット」ボタン |
| `git push` / `git pull` | 「変更の同期」ボタン、または「…」メニュー |
| `git switch` | 左下のブランチ名をクリック |

### ブランチ切り替え時に変更が残っている場合

未コミットの変更があるままブランチ名をクリックして切り替えると、「スタッシュしてチェックアウト」「変更の移行」「チェックアウトの強制」などの選択肢が表示されます。それぞれの意味は[6. ブランチを使った作業](#ブランチを切り替えるときに変更が残っている場合)を参照してください。

### スタッシュした変更を戻す

1. ソース管理の「…」メニューを開く。
2. **スタッシュ** → **スタッシュを適用** または **スタッシュをポップ** を選ぶ。
3. 戻したい退避の一覧から選ぶ。

> 適用はスタッシュを残し、ポップは戻したあとに削除します。

ただし、仕組みを理解するために**まずはコマンドで一度体験する**ことをおすすめします。

## 12. 補足：IntelliJ IDEA での操作（GUI）

IntelliJ IDEA でも、コマンドを使わずに Git 操作ができます。主に **Commit ウィンドウ**（左端のコミットアイコン）と、メニューの **Git** を使います。

### コマンドとの対応表

| コマンド | IntelliJ IDEA での操作 |
|---|---|
| `git clone` | ウェルカム画面の **Clone Repository**（詳細は 4-4-3 を参照） |
| `git pull` | `Git` → `Pull...`、または `Update Project` |
| `git status` | 左の **Commit** ウィンドウに変更ファイルの一覧が表示される |
| `git add` | Commit ウィンドウで、コミットしたいファイルに**チェックを入れる** |
| `git commit` | メッセージを入力して **Commit** ボタン |
| `git commit` + `git push` | **Commit and Push...** ボタン |
| `git push` | `Git` → `Push...` |
| `git diff` | 変更ファイルをダブルクリック（変更前後が左右に並んで表示される） |
| `git log` | 左下の **Git** ウィンドウ → **Log** タブ |
| `git switch` / `git branch` | 画面上部（または右下）の**ブランチ名**をクリック |
| `git restore` | 変更ファイルを右クリック → `Rollback...`（⚠️ 元に戻せません） |

### コミット〜push の手順

1. ファイルを編集する。
2. 左端の **Commit** アイコンで Commit ウィンドウを開く。
3. **Changes** の一覧で、コミットしたいファイルに**チェックを入れる**。
   - 新しく作ったファイルは **Unversioned Files**（未追跡）に表示される。チェックを入れてコミットすると Git の管理対象に加わる。
   - ファイルを新規作成した直後に「Add to Git?」と聞かれた場合は **Add** を選んでもよい。
4. **Commit Message** 欄に変更内容を書く。
5. **Commit** をクリックする（その場で push まで行うなら **Commit and Push...**）。
6. **Commit** のみ行った場合は、`Git` → `Push...` を開き、送るコミットを確認して **Push** をクリックする。

> **ファイルの色の意味**（プロジェクトツリーや Commit ウィンドウ）
> - 緑：新規追加　／　青：変更あり　／　赤茶：未追跡（Git 管理外）　／　灰色：`.gitignore` で無視されている

### ブランチの作成と切り替え

1. 画面上部（または右下）の**ブランチ名**（例：`main`）をクリックする。
2. **New Branch...** を選び、ブランチ名を入力して **Create** をクリックする（作成と同時に移動する）。
3. 既存のブランチに移動するときは、一覧からブランチを選び **Checkout** をクリックする。
4. 未コミットの変更が残っていると、**Smart Checkout** / **Force Checkout** / **Don't Checkout** のダイアログが表示される（意味は[6. ブランチを使った作業](#ブランチを切り替えるときに変更が残っている場合)を参照）。
   - **Smart Checkout**：変更を退避して切り替え、切り替え後に自動で戻す
   - **Force Checkout**：変更を**破棄**して切り替える（⚠️ 元に戻せません）
   - **Don't Checkout**：切り替えをやめる
   - 退避の方式（スタッシュ / シェルフ）は `Settings` → `Version Control` → `Git` の **Clean working tree using** で選べる。
5. 初めて push するブランチは、`Push...` の画面でそのまま **Push** をクリックすればよい（`-u` 相当の設定は自動で行われる）。

### 退避した変更を戻す

- **スタッシュ**：`Git` → `Uncommitted Changes` → `Unstash Changes...` を開き、戻したい退避を選んで **Pop Stash**（戻して削除）または **Apply Stash**（戻して残す）をクリックする。
- **シェルフ**：Commit ウィンドウの **Shelf** タブを開き、対象を右クリック → **Unshelve** を選ぶ。

### コンフリクトの解決

`Pull` や `Merge` で衝突すると、**Conflicts** ダイアログが表示されます。

1. 対象ファイルを選び、**Merge...** をクリックする。
2. 3つに分かれた画面が開く。
   - 左：**自分の変更**　／　右：**相手の変更**　／　中央：**結果（ここが保存される内容）**
3. 各変更の横にある **»**（左の内容を採用）・**«**（右の内容を採用）をクリックして取り込む。中央の結果は直接編集もできる。
4. 上部の **Accept Left**（自分の変更を採用）／ **Accept Right**（相手の変更を採用）で一括で選ぶこともできる。
5. 内容を確認して **Apply** をクリックする。全ファイル終わったら Commit する。

### 困ったとき

| 状況 | 対処 |
|---|---|
| push が rejected された | `Git` → `Pull...` で最新を取り込んでから、もう一度 `Push...` |
| 直前のコミットメッセージを直したい（push 前のみ） | Commit ウィンドウの **Amend** にチェックを入れてコミット |
| add（チェック）を外したい | Commit ウィンドウでチェックを外す |
| ログイン情報を求められる | 4-4-3 の手順で GitHub アカウントを登録する（または Password 欄に PAT を貼り付ける） |

> IntelliJ IDEA のバージョン（New UI / Classic UI）によってボタンの位置が少し異なりますが、メニューの `Git` から同じ操作を探せます。
